## 1. P8 — 中／高級：沿用帳號＋前一等級通過檢查

### 1.1 產品規則

| 規則 | 說明 |
| :--- | :--- |
| **帳號** | 中級、高級場次／申請：**禁止新建 Moodle 帳號**。一律沿用初級（或更早）已建立之帳號與考生編號。 |
| **初級** | 維持現行三情境（全新建帳／補發編號／既有編號）。 |
| **前置等級** | 嚴格鏈：**初級 → 中級 → 高級**（不可跳級）。中級←已通過初級；高級←已通過中級。 |
| **通過範圍** | 前一等級通過**不限講師、不限考場**：全站任一場次通過即算。 |
| **「通過」定義** | 以前一等級的評量規則為準：若該等級**啟用筆試**→須筆試通過 **且** 術科通過；若該等級**不需筆試**→僅術科通過。術科＝外掛 `practicalpass` **或** 對照出缺席活動任一時段〔參〕／Present（舊制相容）。 |
| **查找鍵** | 批次與手動新增**欄位相同**；系統**優先以輸入的 Email** 尋找既有學員帳號（再做前置檢查）。 |
| **資料來源** | 外掛名冊／成績（`local_tm_cert_enrols`）＋等級對照之 `mod_attendance`〔參〕；筆試仍讀對照測驗成績。 |

### 1.2 適用入口（同一套檢查）

1. **申請開課**附帶 CSV（含預覽／確認）  
2. **場次「新增學員」**（單筆＋批次）  
3. （若有）管理手動開課帶名單  

中級／高級：檢查失敗者**不得寫入名冊**（預覽階段即擋下或標紅不可確認）。

### 1.3 預覽／Summary 顯示（講師必看）

上傳／解析後進入與現行類似的 **summary／預覽畫面**，每位學員一列：

| 結果 | 畫面行為 |
| :--- | :--- |
| **合格可加入** | 顯示姓名、Email、**既有考生編號**、標籤「可加入／已通過{前一等級}」 |
| **不合格** | 醒目標示，並列**原因**（可多選／主因）：見下表 |
| **統計列** | 可加入 N 人／不合格 M 人；僅當「可加入」≥1 且講師確認後，才寫入可加入者；不合格者不寫入 |

**不合格原因（固定文案鍵，中英語系）：**

| 代碼（概念） | 講師可見原因 |
| :--- | :--- |
| `account_not_found` | 查無此帳號（Email 對不到 Moodle 使用者） |
| `written_fail` | 前一等級筆試未通過（或尚無成績） |
| `practical_fail` | 前一等級術科未通過（或尚無成績） |
| `prev_level_not_passed` | 前一等級整體未通過（筆試必要時兩者皆需；可作總結標籤） |
| `no_candidate_id` | （可選）有帳號但無考生編號——規格傾向：**視為不可加入**，提示請先完成初級流程 |

> **不創帳：** 即使 CSV 看起來像「全新學員」，中／高級也**不得**走建帳路徑；一律歸為 `account_not_found` 或既有帳不合格。

### 1.4 「前一等級通過」判定（實作準則）

建議函式（概念）：`prerequisite_helper::evaluate(email|userid, targetlevel) → {ok, candidateid, reasons[]}`

1. 解析 Email → userid；找不到 → `account_not_found`。  
2. `prev = basic` if target=intermediate；`prev = intermediate` if target=advanced。  
3. 讀 prev 等級設定：`written_enabled`、筆試門檻、術科門檻。  
4. 術科達標（擇一即可）：  
   - 外掛名冊任一場次 `practicalpass=1`（有分數）；或  
   - 該等級**對照的** `mod_attendance` 活動中，任一時段已有〔參〕／Present（相容外掛上架前舊制）。  
   筆試（若該等級啟用）仍依 Moodle 測驗門檻。  
5. 若僅有部分通過：分別標 `written_fail`／`practical_fail`。  
6. 通過者帶出 `candidate_id`（candidates 表）供 summary 顯示。

**邊界（已定案）：**

- 同一 Email 多場次：任一場次於該等級「整體通過」即算通過（**不限講師／考場**）。  
- 舊制〔參〕：以等級對照的出缺席 **cmid** 為準；請確認對照指向實際登錄術科的活動。  
- 中／高級手動新增與批次：欄位相同、皆不建帳；以 Email 優先查找。  
- 不可跳級（無中級通過不可報高級）。  
- 管理端「強制加入」：P8 **不做**後門；若日後需要另開需求。  
- 初級場次：行為不變。

### 1.5 資料／API 影響（預估）

| 項目 | 變更 |
| :--- | :--- |
| `batch_helper`／`candidate_manager` | 依場次 `certlevel` 分支：basic＝舊三情境；mid/adv＝僅連結＋前置檢查 |
| 申請草稿 `app_learners` | 可存檢查結果快照（可選）或確認當下重算 |
| 語系 | 不合格原因、summary 統計文案 |
| DB | 原則可不新表；若需快取通過狀態可後補 |

### 1.6 P8 驗收清單

- [ ] 初級 CSV：仍可新建帳＋編號。  
- [ ] 中級 CSV：絕不新建帳；查無 Email → summary 明示。  
- [ ] 已通過初級者：summary 顯示原考生編號，可確認加入。  
- [ ] 僅筆試未過／僅術科未過：原因分開顯示。  
- [ ] 高級對中級同上。  
- [ ] 申請預覽與場次新增學員兩入口行為一致。  
- [ ] 未授權使用者不可操作。

## 2. P9 — 場次現場點名（獨立於課程出缺席）

### 2.1 產品規則

| 規則 | 說明 |
| :--- | :--- |
| **用途** | 講師**現場點名**（到課確認），與課程內 `mod_attendance`（術科〔參〕／〔缺〕連動）**完全分離**，資料不互相覆寫。 |
| **入口** | 場次 **［名單］** 頁（`admin/roster.php`）提供「點名」操作。 |
| **紀錄時間** | 每次按下點名須更新 **最後操作時間戳**（server time）與操作者。**只保留最後狀態＋最後點名時間**（不加每次按壓歷史表）。 |
| **統計** | 點名紀錄與統計在**獨立頁／表單**（例：`admin/rollcall.php` 或名單頁分頁），**不**混入 Moodle 出缺席活動畫面。 |

### 2.2 互動（建議 UX）

1. 名單列：每位學員有「到課／未到」或「點名」按鈕；亦可提供「全部標記到課」後再微調。  
2. 按下時立即寫入／更新該學員於**本場次**的點名狀態，並存 `timemarked`（最近一次點名時間）。  
3. 「點名統計」入口：同名單頁頂部連結 → 獨立頁顯示到課人數、未到人數、各學員點名時間、操作者。  
4. 場次已結束：仍可檢視統計；是否允許補點名 → **預設允許講師／管理補登**（實作時可加設定開關）。

### 2.3 建議資料表

`local_tm_cert_rollcall`（表名 ≤ 28）

| 欄位 | 說明 |
| :--- | :--- |
| `id` | PK |
| `sessionid` | 場次 |
| `enrolid` / `userid` | 名冊列或使用者 |
| `status` | `present`／`absent`／`unknown`（實作定常數） |
| `timemarked` | 最近一次點名操作時間 |
| `markedby` | 操作者 userid |
| `timecreated` / `timemodified` | 審計 |

可選擴充（**本階段不做**）：`local_tm_cert_rollcall_log` 留每次按壓歷史；現況單表即可。

### 2.4 與既有 `mod_attendance` 的關係

| 項目 | `mod_attendance`（既有） | P9 點名 |
| :--- | :--- | :--- |
| 目的 | 術科達標→〔參〕／未達標→〔缺〕 | 現場是否到課 |
| 寫入時機 | 存術科成績時 | 講師按點名時 |
| UI | Moodle 出缺席活動 | 外掛名單／點名統計頁 |
| 資料 | `attendance_*` | `local_tm_cert_rollcall*` |

兩者並存、互不取代。

### 2.5 P9 驗收清單

- [ ] 名單頁可見點名入口；無授課／管理權限不可見。  
- [ ] 點名後可在統計頁看到時間與操作者。  
- [ ] 切換到課／未到會更新時間。  
- [ ] Moodle 課程出缺席活動內容不因點名而改變。  
- [ ] 結束場次仍可查看統計。

## 3. P10 — 通過後證書下載（學員自助＋講師代理）

### 3.1 產品規則

| 規則 | 說明 |
| :--- | :--- |
| **學員** | 通過該等級檢定後，可於**自己的頁面**（「我的證書」／學員儀表板）下載對應 **customcert**。 |
| **講師／管理** | 可回溯該場次 → **［名單］**：對「已通過」學員提供**代理下載**按鈕（下載該生該等級證書）。 |
| **顯示時機** | 以**本場整體通過判定**為準（筆試若必要＋術科達標）：一旦判定為通過，名單即顯示通過狀態並附「下載證書」。**與場次是否結束無關**（進行中場次，成績已判定通過也可下載）。 |
| **未通過／未判定** | 未通過或不顯示下載鈕；成績尚未齊全時可視為未判定（無下載）。不提供空證書連結。 |

### 3.2 通過與證書核發

- **通過判定：** 沿用 P5（該場筆試若必要＋術科門檻）。  
- **證書本體：** 沿用 P6／`certificate_helper`＋對照課程 `mod_customcert`。  
- **代理下載：** 講師有權取得「該學員於該證書活動」的 PDF／下載 URL（需 capability 檢查：該場 instructor 或 manage／approve）；不可下載無關場次／無關學員。  
- **學員自助：** 僅能下載自己的證書（既有 `get_own_download_url` 路徑強化：通過後才顯示可下載）。

### 3.3 名單 UI（依通過判定）

| 欄 | 內容 |
| :--- | :--- |
| 通過狀態 | 通過／未通過／未判定（pill） |
| 操作 | **已判定通過** →「下載證書」；其餘 → 無下載或灰色禁用 |

不依場次 open／ended 狀態控制下載按鈕。

### 3.4 P10 驗收清單

- [ ] 學員通過後，「我的證書」可下載；未通過無下載。  
- [ ] 講師於名單：該生**已判定通過**即見通過狀態＋代理下載（場次進行中亦可）。  
- [ ] 場次結束與否不影響下載顯示邏輯。  
- [ ] 代理下載檔案＝該學員證書，非講師本人證書。  
- [ ] 無權限者直接 URL 拒絕。  
- [ ] customcert 未安裝／未對照時有清楚提示，不白屏。

## 4. 階段依賴與風險

```
P4 批次預覽 ──┐
P5 評量通過 ──┼──► P8 前置檢查（重用通過邏輯）
P6 customcert ─┼──► P10 下載／代理下載
名單頁 UI ─────┴──► P9 點名入口＋P10 通過欄
```

| 風險 | 緩解 |
| :--- | :--- |
| 「通過」定義與歷史場次資料不全 | P8 先統一 `assessment_manager`／名冊通過旗標；必要時 migration 回填 |
| 代理下載權限過寬 | 嚴格 session＋enrol 歸屬檢查 |
| 點名與出缺席名稱易混淆 | UI 文案固定「現場點名」；說明與課程出缺席無關 |
| 中高級誤建帳 | 程式路徑硬擋 `create user` when level≠basic |
